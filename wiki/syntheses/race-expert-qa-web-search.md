# Web Search для вопросов о товаре Race Expert

## Решение

Карточка товара остаётся первым источником. Если её недостаточно или покупатель прямо спрашивает об опыте других покупателей, backend может выполнить один быстрый внешний поиск по одному уже перепроверенному товару. Провайдер — Tavily Search API с `fast`, малым числом результатов, ограничением доменов и отключённым full-page/raw-content. Запросы не должны запускать массовый обход или индексирование примерно 5 000 товаров.

Искать можно только в заранее утверждённом списке доменов производителей, поставщиков и выбранных площадок отзывов. Домены по умолчанию запрещены, если их нет в allowlist; поиск не включать, пока стартовый список не проверен.

## Допустимые данные и ответы

- Факты о составе и свойствах брать у производителя или утверждённого поставщика; данные текущей карточки остаются авторитетными для выбранного товара и варианта.
- По отзывам сообщать только субъективную тему, если она повторяется как минимум на двух независимых одобренных страницах об exact-match товаре. Не цитировать отзывы, не передавать/сохранять имена, профили и персональные данные. Короткие релевантные фрагменты могут быть временно переданы финальному вызову модели после удаления очевидных персональных данных; их и полный текст отзыва не сохранять.
- Отзывы не доказывают состав, безопасность, эффективность, дозировку, противопоказания или другой медицинский/объективный факт.
- Ответы — на украинском языке. Покупателю не показывать URL, домены, цитаты или список источников. Источники могут храниться только как внутренняя provenance конкретной попытки; без сырого текста.
- Для вопросов о здоровье backend должен добавлять фиксированный дисклеймер: «Це відповідь штучного інтелекту; інформацію щодо здоров’я потрібно перевірити з фахівцем.»
- При отсутствии точного совпадения, конфликте источников или сбое поиска нельзя угадывать. Если карточка достаточна, отвечать по ней; иначе честно сказать, что данные не удалось подтвердить.

## Результат исследования источников

Публичный каталог Race Expert показывает около 10 000 товаров и включает спортивное питание, витамины и добавки, аксессуары, клубную одежду, сублімовану їжу и категории «Ветеранського спорту». Проверка охватила типовые бренды и страницы по основным группам, а не все SKU каталога.

- Для фактов о товаре найдены официальные домены Maurten, SiS, GU, Precision Fuel & Hydration, 226ERS, SPONSER, Enervit, Huma, Beet It, Nutrend, Nutriversum, PureGold, Myprotein, Optimum Nutrition, BioTechUSA, NOW Foods, Life Extension, Solgar, Swanson, Nature’s Way, ЇDLO, Napiy, РябChick, Camotec, Chamois Butt’r, TRISWIM и SolRX. Для каждого товара всё равно требуется точное совпадение модели и варианта.
- Производитель SPONSER подтверждает украинские сайты `sponser.com.ua` и `sportpro.com.ua`. Пользователь согласовал `nutrend.com.ua` как условный supplier-источник только для товаров NUTREND; сайт сам заявляет статус дистрибьютора, manufacturer-side подтверждения пока нет.
- Основные кандидаты для товарных отзывов — `fit.rozetka.com.ua` (одна площадка вместе со всеми поддоменами Rozetka) и `prom.ua`; `makeup.com.ua` условно для добавок, `epicentrk.ua` — низкоприоритетный резерв. Виджет Revizion на Race Expert содержит отзывы о магазине, а не точном товаре.
- Для товаров бренда Race Expert и части аксессуаров независимое покрытие точных SKU не подтверждено.

## Текущий статус и следующий шаг

Backend содержит Tavily provider/config, ограниченные exact-product доказательства, активный prompt v18, приватные attempt metadata, JSON `POST /api/v1/ask` и SSE `POST /api/v1/ask/stream`. JSON endpoint оставлен совместимым. Локальный UI показывает typing-индикатор и части ответа; история не отображается и живёт только в памяти страницы. Streaming и typing проверены offline, на синтетическом browser preview и в контейнере с отключённой сетью. Контракт для будущего backend сайта и отдельный brief Rozetka-подобного виджета готовы. `/ready` выполняет read-only `SELECT 1` для проверки каталога; `/health` показывает liveness. Сам storefront и внешний backend сайта не менялись и пока не подключены.

`/api/v1/ask` повторно разрешает точный товар на каждом запросе и принимает необязательное поле `history` с 0–9 предыдущими `user`/`assistant` сообщениями; старые клиенты без него продолжают работать. Общий предел JSON body — 16 384 байта: отправитель удаляет самые старые целые history messages, если нужно освободить место, и не сокращает текущий вопрос. Локальный UI держит не более 10 сообщений всего в памяти вкладки и очищает их при новом поиске товара или перезагрузке. Backend передаёт прошлые реплики модели как недоверенный контекст, а не источник фактов или инструкции; историю не логирует и не сохраняет. Зависимый личный health/safety follow-up учитывает только прошлое сообщение пользователя и сохраняет фиксированный отказ без дозировки.

Prompt v18 добавляет сбалансированный ответ о спортивном применении: когда точный источник подтверждает общее назначение для активных спортсменов/после тренировки, но не специальное применение в названном спорте, ответ должен содержать обе части. Не выводить из общего назначения личную безопасность, дозировку или эффект.

На 23 ноября focused offline tests прошли: 97 passed; полный suite: 216 passed и 4009 subtests. Локальный image `race-expert-product-qa:stream-local-check` собран с `--network=none`; smoke прошёл с `--network none` и synthetic dependencies, подтвердив prompt hashes v12–v18, `/health`, `/ready`, JSON ask и SSE ask. Browser preview проверил появление/скрытие typing и сборку частей ответа на synthetic stream. Платные OpenAI/Tavily вызовы, storefront/backend сайта, staging и VPS не затрагивались.

Пользователь утвердил стартовый набор hostnames из исследования; `SOURCE_REGISTRY` теперь перечисляет разрешённые hostnames без wildcard и ограничивает factual domains по брендам. Для SPONSER добавлены `sponser.com.ua` и `sportpro.com.ua`; `nutrend.com.ua` разрешён только для NUTREND как условный, self-claimed поставщик. Для отзывов разрешены `fit.rozetka.com.ua` и `prom.ua`, Rozetka aliases объединены в одну независимую группу. Makeup, Epicentr, SaltStick redirect и holdout бренды не включены. Набор не покрывает каждый артикул каталога.

Внутренний сервер отправляет Tavily только product identity и фиксированную тему, не сырой текст вопроса. Результаты фильтруются по HTTPS hostname, exact product identity и варианту. Отзывы проходят только при общей распознаваемой теме минимум из двух независимых групп; имена/контактные данные удаляются из передаваемых фрагментов. Исходные excerpts в SQLite не хранятся.

В live E2E 20 ноября проверили 50 товаров × 10 вопросов: после перезапуска локального launcher получено 500/500 успешных ответов, Tavily вызывался 217 раз, 5 записей прошли фильтр имени товара, но ни одна не подтвердила нужный точный вкус/объём/фасовку. В 283 финальных попытках было `search_status=skipped`; это означает, что Tavily не вызывался, но само по себе не доказывает, что каждый пропуск был правильным — классифицируй решения по конкретным вопросам. В отчёте также зафиксированы 21/50 нерелевантных ответов, 41/50 ответов с количеством/инструкцией при personal-health вопросах и обрыв SQL-туннеля при зелёном `/health`.

После прогона v14 добавил fail-closed `product_related`, фиксированный отказ в персональном health/dose сценарии и `verified_product_name`; `/ready` отделён от `/health`. v16 live check запустил Tavily, но ответ остался слишком осторожным. Prompt v17 требует использовать подтверждённое производителем общее назначение для спортсменов/после тренировки, когда вопрос относится к виду спорта, и отвечать без упоминания внутренней карточки. Offline-набор v17 и mock container smoke прошли; bounded live UI E2E v17 теперь также завершён успешно: каталог, поиск Tavily, exact-source filter и OpenAI answer path сработали. Подробности — в [production-readiness synthesis](race-expert-qa-production-readiness.md), [отчёте Live E2E](../../docs/test-harness/qa-live-50-products-500-questions-2026-11-20.md) и [плане адаптации](../../docs/superpowers/plans/2026-11-20-product-qa-reliability-follow-up.md).

Пользователь подтвердил наличие `TAVILY_API_KEY`; ни отдельный key-файл, ни чтение `.env` для этого не нужны. Текущий runtime и локальный launcher принимают прямой ключ либо file-вариант, но не оба одновременно. Секретные значения нельзя читать, выводить или передавать программисту сайта.

Production ещё требует установки и приёмки на целевом VPS: образ для его архитектуры, route в существующем HTTPS reverse proxy (или отдельный hostname/DNS/TLS, если действующий host использовать нельзя), MySQL с доверенным CA и проверкой имени, отдельный read-only пользователь на пять таблиц, постоянный SQLite volume, backup/restore и эксплуатационные проверки. Backend сайта и Product QA планируются на одном VPS; отдельная DNS-запись не нужна при подключении точного API path через существующий HTTPS host. Подготовка к handoff сама по себе не подключает storefront и не выполняет deploy.

Официальные технические ссылки в спецификации: [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search), [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling).
