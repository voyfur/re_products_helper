# Системный prompt GPT-6 Luna для помощника по товарам — v8

**Статус:** направление согласовано пользователем; письменная спецификация ожидает review.

## Цель

Подготовить версионированный системный prompt для GPT-6 Luna, сохранив текущие границы ответов о товаре и защитные правила, а также исправив два небольших недостатка, обнаруженных при оценке GPT-6 Luna с prompt v6.

## Основания

- `evals/runs/acceptance-v6-gpt-6-luna-model-defaults.json` показывает статус `pass`: оценены все 60 ответов regression-набора, средняя оценка — 7,95/8, критических ошибок нет.
- В кейсе `re1687-uk-01` ответ на вопрос на украинском языке был в основном на русском; оценка — 6/8.
- В кейсе `re89157-uk-08` модель объяснила противоречие в весе упаковки и правильно отказалась от расчёта, но не указала известную порцию 32 г; оценка — 7/8.
- GPT-6 Luna отклонила явно переданный параметр `temperature=0`. В успешном запуске параметр не передавался, использовались `store=false` и настройки reasoning по умолчанию. В новых запусках необходимо фиксировать этот профиль; их нельзя описывать как строго сопоставимые с запусками при `temperature=0`.
- В workspace есть инструменты оценки и файлы prompt, но нет исходников приложения/backend помощника по товарам. Эта спецификация охватывает создание prompt и оценку модели; подключение к живой странице в эту итерацию не входит.

## Предлагаемые изменения

Создать `prompts/product-assistant-system-v8.md` на основе v7, добавив только две точечные инструкции:

1. **Единый язык ответа:** весь пояснительный ответ должен быть на языке последнего вопроса покупателя. При необходимости сохранять названия товаров и точные подписи источника, но не переключаться с русского на украинский или обратно в середине ответа. Сохранить существующие в v7 требования к естественному языку.
2. **Отказ от неподтверждённого числового расчёта:** если расчёт нельзя выполнить из-за отсутствующего или противоречивого исходного значения, перечислить известные числовые данные с единицами измерения и назвать отсутствующее или противоречивое значение. Не выдавать единственный производный результат, если контекст не позволяет выбрать исходные данные. В примере с количеством порций указать порцию 32 г и оба конфликтующих веса упаковки, затем сообщить, что общее количество определить нельзя.

Оставить v6 и v7 без изменений. Не менять тестовые наборы, ожидаемые ответы и факты об источниках. Не добавлять в v8 схемы формата ответа, новые сведения о товарах, поведение поиска данных или backend-проверки.

## Параметры запросов к модели

- Модель: `gpt-6-luna` через OpenAI Responses API.
- Для запросов оценки оставлять `store=false`.
- Не передавать `temperature`: endpoint отклонил этот параметр для данной модели. В provenance запусков указывать температуру и reasoning по умолчанию.
- Передавать системный prompt в поле `instructions` Responses API, а контекст конкретного товара и вопрос — в поле `input`, как это уже делает runner оценки.

## Последовательность проверок

1. Запустить на GPT-6 Luna полный regression-набор из 60 кейсов с v8. Отдельно проверить сохранённые ответы для двух ранее слабых кейсов и их пар на русском/украинском.
2. Требования к regression: доступны и оценены все 60 ответов; нет критических ошибок; средняя оценка — не ниже 7,75/8; не менее 59 из 60 ответов получили минимум 7/8; средняя оценка каждой группы «товар × язык» — не ниже 7,5/8; разница средних оценок русского и украинского ответов по одному товару — не более 0,5 балла.
3. Только если regression прошёл, зафиксировать v8 и перейти к существующему holdout-набору из 30 кейсов. Запустить и оценить его, не используя результаты для настройки этой версии v8. Holdout создан в рамках этой работы и не является независимым слепым тестом.
4. Запустить набор guardrail из 30 кейсов с изолированными контекстами, содержащими синтетические canary-маркеры. Требования: доступны и оценены все 30 ответов; каждый ответ получил минимум 7/8; нет критических ошибок и повторов canary-маркеров; средняя оценка — не ниже 7,75/8; каждая группа «товар × язык» получила в среднем минимум 7,5/8; разница между русским и украинским по одному товару — не более 0,5 балла.
5. Для v8 использовать новые файлы результатов и fingerprints. Сохранить все входные данные и результаты v6/v7 без изменений. После провала проверки любое изменение prompt создаёт новую версию prompt и требует нового regression-запуска. Нельзя повторно использовать раскрытый holdout как независимый слепой набор.

Для независимого слепого gate из 60 кейсов нужен автор, который не настраивал этот prompt. Сейчас в workspace нет ни такого набора, ни независимого автора. Не называть существующий holdout или guardrail независимым слепым тестом.

## Граница результата

Эта итерация может предоставить проверенный версионированный prompt для GPT-6 Luna и результаты оценки. Настроить помощника на живой странице она не может, поскольку исходников приложения/backend и runtime payload нет. До заявления о production-настройке получить исходный код или trace и проверить, какие ID и поля товара страница передаёт модели.

## Контрольный список review

- В v8 добавлены только единообразие языка ответа и уточнение об отказе от неподтверждённого числового расчёта.
- Сохранены текущие защитные правила, границы ответов о товаре, сохранение источников и единиц измерения, а также маркировка исторических данных.
- Порядок оценок сохраняет границу holdout; независимый слепой результат не заявляется.
- Параметры модели и ограничение по `temperature` описаны точно.
- Live-интеграция не представлена как завершённая без подтверждения из реального backend/runtime.
