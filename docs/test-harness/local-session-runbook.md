# Локальный запуск Q&A через SSH-туннель

Этот сценарий предназначен только для локальной QA-сессии. Он создаёт SSH-туннель через VPS-61125 к MySQL, поднимает приложение только на `127.0.0.1` и завершает туннель вместе с приложением.

## Почему здесь нет проверки сертификата MySQL

В этой одобренной локальной сессии SSH проверяет ключ VPS через системный `known_hosts` (`StrictHostKeyChecking=yes`). Через туннель приложение устанавливает отдельное MySQL-соединение с обязательным TLS. Версия TLS должна быть `TLS 1.2` или `TLS 1.3`; plaintext запрещён.

Проверка CA и имени MySQL-сервера для этой сессии отключена, потому что используемый MySQL endpoint предъявляет самоподписанный сертификат без SAN с именем endpoint. Это не подтверждает криптографически личность MySQL-сервера. Такое разрешение относится только к запуску на локальном компьютере через указанный SSH-туннель. Не используй этот режим в постоянном backend, staging или production: для них нужны доверенный CA и проверка имени сервера.

## Параметры локального доступа

В QA/.env должны быть заданы SSH_HOST, SSH_USER, SSH_PORT, SSH_PRIVATE_KEY_PATH, MYSQL_HOST, MYSQL_PORT, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD_FILE, OPENAI_API_KEY_FILE и ровно один из TAVILY_API_KEY или TAVILY_API_KEY_FILE; JOURNAL_PATH необязателен. Запускатель читает значения только через строгий allowlist-парсер. Если указан TAVILY_API_KEY_FILE, отдельный файл ключа должен иметь права 0600 или строже; .env также должен оставаться с правами 0600. MySQL/OpenAI секреты загружаются из отдельных файлов; для Tavily допускается прямое значение в .env или отдельный файл. Значения не печатай и не передавай в аргументах команд.

## Запуск

Из каталога `QA` создай окружение и установи закреплённые runtime-зависимости:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Убедись, что `QA/.env` и файлы в `QA/secrets/` имеют права `600`, а приватный SSH-ключ уже доверен для доступа к VPS. Файл `.env` читается запускателем по allowlist ключей; он не запускается как shell-код и не печатается. Дублирующиеся ключи, отсутствие или одновременная настройка обоих вариантов Tavily, неизвестный SSH-хост, другая схема базы или небезопасные права файлов блокируют запуск с обобщённым кодом ошибки без вывода секретов.

Запусти:

```sh
.venv/bin/python scripts/run_local_session.py --env-file .env
```

Запускатель проверит SSH-туннель, подключение к выбранной схеме, `SELECT 1` и доступ на чтение метаданных пяти Q&A-таблиц через `LIMIT 0`. Строки товаров он не читает при старте. SSH-клиент отправляет keepalive каждые 30 секунд и закрывает туннель после трёх проверок подряд без ответа. Если соединение потеряно во время QA, перезапусти запускатель. После успешного старта открой `http://127.0.0.1:8787`. Нажми Ctrl+C, чтобы завершить приложение и закрыть SSH-туннель.

Проверки `/health` и `/ready`, а также запуск не вызывают OpenAI или Tavily. `/health` подтверждает только, что процесс отвечает; `/ready` выполняет read-only `SELECT 1` для проверки каталога и возвращает `503`, если каталог недоступен. Во время длительного QA-прохода проверяй `/ready`: зелёный `/health` сам по себе не означает, что SQL-туннель работает. Q&A отправляется провайдерам только после явной отправки вопроса. Приложение читает только пять таблиц карточки товара; учётная запись сейчас имеет более широкие read-only grants. До любого постоянного развёртывания владелец БД должен выдать отдельного пользователя с `SELECT` только на нужные пять таблиц, а также подтвердить доверенную TLS-конфигурацию. `PRODUCT_QA_API_KEY_FILE` — отдельная настройка постоянного server-to-server API, локальный launcher её не загружает. Staging, storefront и production этой локальной инструкцией не разрешаются.

## Если туннель не запускается

- `ssh_tunnel_failed_check_known_hosts_and_vps_key` — проверь, что ключ VPS уже записан в системный `known_hosts`, приватный ключ доступен и его права ограничены.
- `ssh_tunnel_timeout_check_vps_and_mysql_route` — проверь доступность VPS и маршрут от VPS к MySQL.
- `mysql_tls_not_active` или `mysql_tls_version_unacceptable` — запуск прекращается; plaintext fallback нет.
- `mysql_connection_failed` — проверь доступ к QA-секрету пароля и параметры MySQL, не вставляя их в терминал или чат.
