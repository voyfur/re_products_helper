# Intent: отдельный тестовый стенд AI-помощника по товарам

**Статус:** утверждён пользователем для подготовки спецификации (2026-11-11).

## Цель

Создать отдельный HTML-стенд для проверки GPT-6 Luna с системным prompt v11 на вопросах о конкретных товарах и для ведения долговременного журнала тестовых вопросов и ответов, который поможет корректировать помощника и готовить новые тесты.

## Пользователь

Внутренний пользователь проекта — тестировщик, который ищет товар по артикулу, проверяет его данные, задаёт вопросы и возвращается к истории проверок.

## Основной сценарий

1. Пользователь вводит артикул и нажимает «ОК».
2. Стенд ищет соответствующую запись товара в базе.
   - Если товар не найден, стенд сообщает об этом, сохраняет введённый артикул в поле и позволяет исправить запрос.
   - Если найдено несколько совпадений, стенд показывает варианты для выбора.
   - При сбое базы стенд показывает нейтральную ошибку без технических подробностей и предлагает повторить поиск.
3. Стенд показывает карточку выбранного товара: название, артикул/model/SKU, описание, характеристики и локализованную подпись наличия. Цену показывать только после подтверждения валюты; внутренние ID и технические флаги по умолчанию скрыть.
4. До первого вопроса карточка показывает русскую и украинскую версии данных. Для каждого вопроса стенд автоматически использует версию контекста на языке этого вопроса и показывает соответствующие языковые данные.
5. Пользователь задаёт вопрос; GPT-6 Luna отвечает с системным prompt v11 и контекстом выбранного товара.
6. Каждый отправленный вопрос сохраняется в истории для просмотра и использования при подготовке новых тестовых вопросов.

## История

- История является долговременным системным журналом для последующей корректировки и анализа, а не только временным списком в браузере.
- Для каждого вопроса сохраняются текст, время отправки, связь с товаром (артикул и ID), ответ модели при успехе, название модели, версия системного prompt и результат запроса.
- Если GPT/API не вернул ответ, вопрос всё равно записывается со статусом ошибки и без ответа; пользователь видит нейтральное сообщение и может повторить запрос. Технические подробности провайдера не показываются.
- Снимок контекста товара в истории по умолчанию не хранится.
- В первом этапе история не удаляется автоматически; конкретные действия очистки и администрирования определить в спецификации потока.

## Границы и ограничения

- Это отдельный внутренний тестовый стенд без интеграции в сайт и без доступа покупателей.
- Ответы модели ограничены данными выбранного товара; сведения других товаров и отзывы не включать.
- Ключ OpenAI использовать только на серверной стороне; не помещать его в HTML или JavaScript браузера.
- Доступ к базе проектировать только для чтения. Секреты из `.env` не запрашивать и не копировать.
- До утверждения этого intent, а затем спецификации пользовательского потока реализацию не начинать.

## Следующий шаг

Подготовить спецификацию пользовательского потока: поиск и выбор товара, карточка, вопросы и ответы, журнал истории, ошибки и повторные попытки. После утверждения спецификации можно переходить к планированию реализации.
