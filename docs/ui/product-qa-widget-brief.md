# Виджет Product QA для Race Expert

## Цель

Подготовить описание интерфейса для frontend-разработчика `raceexpert.com.ua`. Визуальный образец — присланный пользователем сценарий Rozetka AI: небольшая плавающая кнопка открывает боковую панель с карточкой товара, вопросами-подсказками, перепиской и закреплённым полем ввода. Использовать брендинг и товарные данные Race Expert; не копировать название или графику Rozetka.

## Сценарий покупателя

1. На странице товара покупатель открывает кнопку «Запитати про товар».
2. Панель показывает компактное резюме уже открытой карточки Race Expert. Это только интерфейсная часть; весь товарный снимок сервису не отправляется.
3. Покупатель нажимает подсказку или вводит свой вопрос.
4. Backend сайта вызывает `POST /api/v1/ask/stream`, передавая артикул, вопрос и при наличии до девяти предыдущих сообщений текущего товара.
5. Пока сервис формирует ответ, показывается typing-индикатор; текст ответа появляется по частям на украинском языке. До десяти сообщений хранятся только как скрытый временный контекст в памяти страницы, без отдельной истории/счётчика и без постоянного хранения.

## Макет

- **Desktop:** плавающая заметная кнопка на странице товара; открытая панель справа, с доступной областью прокрутки.
- **Mobile:** панель занимает почти всю высоту экрана; верхняя полоса остаётся видимой, поле ввода закреплено снизу и не перекрывает ответ.
- **Header:** Race Expert AI, необязательная маркировка beta, кнопка закрытия и понятный возврат фокуса на launcher.
- **Product card:** название и основные сведения уже загруженной страницы; никаких цены, корзины или заказов в API Product QA.
- **Suggestions:** несколько коротких вопросов, относящихся к текущему товару. Не обещать факты, которых нет в карточке или approved sources.
- **Conversation:** скрытый контекст предыдущих реплик не выводится отдельным списком, счётчиком или payload. Текущий buyer-facing вопрос и ответ можно показать в обычном интерфейсе; ответ отображается обычным текстом, без HTML из модели, ссылок или источников.
- **Composer:** multiline input внизу, send button, ограничение 2000 символов и короткая доступная подпись.

## Ожидание и ошибки

- Для потокового POST показывать typing-индикатор от отправки до `done`, `error` или обрыва соединения; отображать `delta` сразу, `replace` трактовать как полную замену ответа.
- Не показывать сообщение о начале веб-поиска: SSE контракт не содержит отдельного события поиска.
- После `done` сохранить текущий успешный turn во временную память той же страницы/товара; при ошибке отбросить частичный ответ и не добавлять turn. Смена товара или перезагрузка очищает память.
- Для `product_not_found` предложить обновить страницу товара; для неоднозначного товара не выбирать вариант автоматически.
- Для `rate_limited` попросить подождать; для `catalog_unavailable` или `answer_unavailable` показать спокойное сообщение и разрешить ручную повторную отправку.
- Не показывать bearer credential, provider error, stack trace, внутренние коды, время поиска, названия доменов или URL.
- Если запрос оборвался по сети, оставить вопрос в панели и дать пользователю отправить его снова; не повторять оплачиваемый запрос в бесконечном цикле.

## Доступность и приватность

- Полная работа с клавиатуры; логичный порядок Tab, видимый focus, Escape закрывает панель.
- При открытии перевести фокус внутрь; при закрытии вернуть его на launcher. Не удерживать фокус за пределами модальной mobile-панели.
- Использовать `aria-expanded`, `aria-controls`, доступные названия кнопок и `aria-live="polite"` для общего статуса и новых ответов.
- Сохранять нормальный перенос и прокрутку длинного ответа, не скрывая поле ввода на узком экране.
- Frontend сайта отправляет `{ article, question, history? }` в собственный backend; `history` — до девяти предыдущих `{ role, content }` этой страницы и товара. Backend добавляет server-side `Authorization: Bearer …` при вызове Product QA.
- История остаётся скрытым недоверенным контекстом, не доказательством и не инструкцией; Product QA не сохраняет её отдельно. Не добавлять постоянное хранилище или endpoint истории.
- Не передавать имя, телефон, email, аккаунт, корзину, заказ, историю других сессий, цену или полный HTML/product snapshot. Не записывать ключи в browser storage, telemetry или source maps.

## Вне этого этапа

Этот brief не реализует storefront-компонент и не подключает его к живому Race Expert. После готовности backend API frontend-разработчику понадобятся URL тестового окружения и отдельный ограниченный site-to-service credential. Production URL, TLS/reverse proxy и выдачу доступа владелец проекта согласует отдельно.
